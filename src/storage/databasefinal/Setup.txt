UC DATABASE SUBSYSTEM — PLUG & PLAY INTEGRATION GUIDE
=====================================================

FILES REQUIRED
--------------
You must include the following three classes in your project:
  • QueueManager.java
  • BatchManager.java
  • DatabaseManager.java

These files depend only on:
  - org.json (JSONObject / JSONArray)
  - exceptions.*  (DatabaseException, QueueException, BatchException)
  - util.Logger   (optional but recommended for logging)


-------------------------------------------------------------
STEP 1: DIRECTORY STRUCTURE
-------------------------------------------------------------
All files are stored under a base folder called "database/".

Typical layout:
  database/
    global/
      bot.json
    server/
    user/

These directories can be customized in your own DependencyManager
or startup logic.


-------------------------------------------------------------
STEP 2: RAW I/O BINDINGS
-------------------------------------------------------------
QueueManager never touches disk directly.
You must bind three raw file operations before using it:

Example (in your startup code):

    QueueManager.RawIO.bindLoader(DatabaseManager::readJSONRaw);
    QueueManager.RawIO.bindWriter(DatabaseManager::writeJSONRaw);
    QueueManager.RawIO.bindMover(DatabaseManager::moveToCorrupt);

This allows the QueueManager to read/write actual files using
DatabaseManager’s low-level helpers.


-------------------------------------------------------------
STEP 3: INITIALIZATION SEQUENCE
-------------------------------------------------------------
Typical startup order:

1) Initialize logger (optional)
2) Initialize QueueManager bindings (above)
3) Create folders if missing (DatabaseManager.createFolder)
4) Ensure required JSON files exist (DatabaseManager.createJSON)
5) Ready to use DatabaseManager methods

You do NOT need to start any thread manually.
QueueManager launches its worker automatically on class load.


-------------------------------------------------------------
STEP 4: CONFIGURATION
-------------------------------------------------------------
You can tune QueueManager behavior via static config values:

    QueueManager.Config.CACHE_TTL_MILLIS = 5 * 60_000;   // flush idle files after 5 min
    QueueManager.Config.BATCH_JOB_FLUSH_THRESHOLD = 100; // flush early after 100 ops
    QueueManager.Config.CACHE_MEMORY_CAP_BYTES = 500L * 1024 * 1024; // 500 MB cache
    QueueManager.Config.WORKER_IDLE_POLL_MS = 1000;      // maintenance every 1s
    QueueManager.Config.MAX_TOTAL_RETRIES = 5;           // max flush retries
    QueueManager.Config.DEBUG = true;                    // verbose logs

All defaults are safe for production.
Changing them is optional.


-------------------------------------------------------------
STEP 5: HOW TO USE IN YOUR CODE
-------------------------------------------------------------
You interact ONLY with DatabaseManager — never directly with the queue.

READS (instant, cached):
    JSONObject obj = DatabaseManager.readJSON("database/global/bot.json");
    Object val = DatabaseManager.readJSONPath("database/global/bot.json", "metadata.owner");

WRITES (batched):
    DatabaseManager.writeJSONPath("database/global/bot.json", "metadata.owner", "Luna", true);

The write request:
  • Applies immediately to the in-memory cache.
  • Is queued for flush later by QueueManager.
  • Will be written to disk in batches or on shutdown.

Manual flush (optional):
    QueueManager.flushAll();   // forces all dirty files to disk


-------------------------------------------------------------
STEP 6: SHUTDOWN
-------------------------------------------------------------
Before your application exits, ensure a clean flush:

    QueueManager.flushAll();

This writes all pending changes to disk safely.


-------------------------------------------------------------
STEP 7: EXCEPTION HANDLING
-------------------------------------------------------------
- DatabaseException → errors at the DBM level (invalid path, bad JSON)
- QueueException → issues during queue operations or flush
- BatchException → invalid batch construction or malformed path

All methods in DatabaseManager throw these as needed.


-------------------------------------------------------------
STEP 8: EXTENDING
-------------------------------------------------------------
You can add new JSON operations easily:

1) Create a builder in BatchManager (buildXYZPath).
2) Add a matching DatabaseManager public method that calls it.
3) QueueManager handles the rest automatically.

Examples already included:
  - writeJSONPath
  - removeJSONPath
  - appendJSONArray
  - renameJSONKey
  - moveJSONPath
  - sanitizeJSON


-------------------------------------------------------------
STEP 9: TESTING
-------------------------------------------------------------
You can enable live debug output:

    QueueManager.Config.DEBUG = true;

and watch:
    • Cache hits / misses
    • Batch validation
    • Queue flushes
    • Maintenance cycles

If you see continuous maintenance logs, it means the worker
is alive and waiting — this is normal.


-------------------------------------------------------------
SUMMARY OF ROLES
-------------------------------------------------------------
DatabaseManager  → Public API (reads/writes, safe high-level calls)
BatchManager     → Builds grouped JSON operations (batches)
QueueManager     → Handles caching, deferred flushes, I/O safety


-------------------------------------------------------------
TYPICAL USAGE FLOW
-------------------------------------------------------------
DatabaseManager.writeJSONPath() →
    builds a Batch →
        passes to QueueManager.enqueueBatchAndGet() →
            edits cached JSON →
            queues write op →
            flushes later to disk


-------------------------------------------------------------
EXAMPLE MINIMAL STARTUP
-------------------------------------------------------------
    public void onReady() {
        Logger.init();

        QueueManager.RawIO.bindLoader(DatabaseManager::readJSONRaw);
        QueueManager.RawIO.bindWriter(DatabaseManager::writeJSONRaw);
        QueueManager.RawIO.bindMover(DatabaseManager::moveToCorrupt);

        DatabaseManager.createFolder("database");
        DatabaseManager.createFolder("database/global");

        if (!DatabaseManager.fileExists("database/global/bot.json"))
            DatabaseManager.createJSON("database/global/bot.json");

        System.out.println("Database system initialized.");
    }


-------------------------------------------------------------
TROUBLESHOOTING
-------------------------------------------------------------
• If you see "Queue read error" → the raw loader isn’t bound.
• If files don’t flush → check TTL or call QueueManager.flushAll().
• If corrupt files appear → inspect /database/corrupt/ folder.
