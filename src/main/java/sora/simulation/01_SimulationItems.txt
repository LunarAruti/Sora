Sora Dungeon Item Library
=============================

Purpose
- This file is the design reference for dungeon items.
- The code-side library lives in sora.simulation.items.DungeonItemLibrary.
- Editor support should eventually place items from the library, not create new item definitions.
- The artifact editor should only place map-based items.
- Interactable items stay in the library for inventory, loot tables, and container contents, not direct artifact placement.
- Runtime placed items use cell coordinates, not grid intersections.
- Placeholder visuals are deliberately blocky and readable until real textures exist.

Shared Data Rules
- id: stable item id used in artifact JSON and runtime lookups.
- name: display name.
- kind: map or interactable.
- category: broad behavior group.
- properties: item-specific defaults.
- placement: cell or grid.
- requires_wall: true when the editor must find a touched wall and save the direction facing away from it.
- cell_based, grid_based, map_based, and detail are derived flags also present in the library defaults.
- Map items use position/direction from the placed artifact item.
- Interactable items use inventory_size for grid inventory placement.
- Player inventory is a 10 by 15 cell grid for now.
- Inventory entries store item_id, x, y, quantity, and per-instance properties.
- Inventory items are not rotatable yet; inventory_size is used exactly as defined.
- Inventory placement must stay inside the grid and cannot overlap another item.
- Inventory quantity cannot exceed the item's can_stack value.
- Interactable world items default to pickup behavior.
- Pickup first fills an existing stack for the same item id, then uses the next open inventory slot.
- Pickup copies the world item id and current properties into inventory, then marks that seed-spawned world item deleted in persistent item state.
- Picked-up world items keep only their deleted marker in persistent item state. Runtime properties such as fuel_remaining and is_on move into the inventory copy.
- If no stack or open slot is available, interaction adds a "Your inventory is full." notification.
- Container contents should use inventory-style slots:
  contents: [{ item_id, x, y, quantity, properties }]
- Locked objects store required_key_id.
- Keys store key_id.
- Tools do not store what they can affect. The target object stores properties such as can_be_pried_open.
- Effects should be referenced by effect_id. The effect system owns duration, damage, stamina, poison, etc.
- Food uses hunger_amount to start the Eating effect when used. Food is consumed on use unless hunger is already full.
- Lantern oil uses fuel_amount to refill a selected portable lantern. Spawned oil rolls fuel_amount between fuel_amount_min and fuel_amount_max.
- Item use can be triggered from the item context menu or by pressing E while hovering an inventory/container item.
- E is the default keyboard command for an item's primary use, but the public verb can differ by item. Examples: food shows Eat, lantern oil shows Fill, notes show Read.
- Inventory/container Use actions should only appear when the behavior is currently wired. Placeholder-only uses stay hidden until implemented.
- Map fragments and written notes now expose Read. Reading opens a centered document panel, keeps the game running, and closes with Tab or Escape.
- Bandages apply Regeneration. Antitoxin is drunk and applies Neutralization. Endurance draught is drunk and applies Elevated Stamina plus Endurance Boost.
- Inventory/container context menus should only show actions the item supports. Decorative or non-usable items should not show Use or Equip. This is controlled by code-side action predicates so item-specific rules can be expanded later.
- Lantern oil enters a selection mode. The hovered item is outlined blue if it is a valid lantern target or red if it is invalid. No item hovered means no outline. Tab cancels the mode; Esc cancels and closes the active inventory/container menu.
- Section headings below are stable ids, not public labels. Public display names are defined in DungeonItemLibrary and can change without breaking saved artifacts.
- interactable: true means the game can target the map object or world item with E/Q.
- can_stack: numeric max quantity allowed in one inventory stack. Missing can_stack means a max stack of 1.
- loot_weight: numeric container loot weight for interactable inventory items. 0 means the item is excluded from random loot.

Current Runtime Interactions
- The two closest assigned interactions use E and Q. One object may consume both buttons if it has two actions.
- Objects with only one action use the standard nearest-object assignment: closest gets E, second closest gets Q.
- Object names render above their assigned action text. Two-action objects use one white cell outline.
- Wall-mounted lamps: Turn on or Turn off.
- Portable floor lantern: E Turn on or Turn off, Q Pick up.
- World interactable items: E Pick up.
- Bomb: E Pick up, Q Light bomb.
- Map fragment and written note: E Pick up, Q Read.
- Chest, storage barrel, and supply crate while holding nothing: E Open, Q Push.
- Empty supply crate while holding nothing: Push.
- Utility table, archive shelf, bone remains, and collapsed rubble: E Search.
- Record table: E Save, Q Menu.
- Control lever: E Toggle.
- Hanging chains: E Pull.
- Toxic gas vent: E Inspect.
- Turn on/off, Pick up, Search containers, grid item movement/drop, usable consumables, and Read have concrete behavior right now. Other actions are placeholders for later systems.

Light Fuel Rules
- Map lights initialize into persistent item state when their loaded area is generated.
- Initial fuel_remaining is seeded per light from 0 to 1000.
- A loaded light loses 1 fuel per second only while it is on.
- Unloaded lights do not drain fuel.
- Turned-off lights do not drain fuel.
- In the last 50 fuel, light radius shrinks proportionally until it reaches 0.
- At 0 fuel, the light turns off and cannot be turned back on.
- Picked-up floor lanterns copy their current fuel_remaining and is_on values into inventory before the world item is marked deleted.
- Floor lanterns placed or dropped onto the world start off; they only emit light after being turned on.
