PNG / PIXEL GENERATOR SPEC

Purpose
- Generate PNG output from a 2D token grid.
- Generate PNG output from a 2D direct-color grid.
- Primary use case is pixel art / cell art.
- Transparency must be literal PNG transparency.

Core Design
- Input grid type is String[][].
- Parallel input grid type is Colors.Color[][].
- Each grid cell stores one color token.
- Direct-color cells store exact RGB values through the shared tools Colors.Color object.
- Tokens may be multi-character.
- Examples:
  - b = black
  - r = red
  - lb = light blue
  - carrot = carrot orange
  - emerald = emerald green
  - . = transparent
- Token lookup is case-insensitive after normalization.
- Null and blank cell values are also treated as transparent.

Public API
- PixelArt
  - Holds the source grid, preferred width, preferred height, exact output path, border size, and border color.
  - Use this when you already have the final String[][] grid in memory and just want to render it.
- PixelColorArt
  - Holds the source Colors.Color[][] grid, preferred width, preferred height, exact output path,
    border size, and exact Colors.Color border color.
  - Null grid cells render as fully transparent.
  - Non-null grid cells render as exact opaque RGB values.
  - Use this only when you need exact RGB per cell instead of palette tokens.
- PixelGridBuilder
  - Mutable helper layered over the PixelArt render contract.
  - Owns a transparent-by-default token grid plus the same render metadata as PixelArt.
  - Can produce a PixelArt snapshot or render directly through PixelGenerator.
  - Supports direct cell editing, background fill, flood fill, point-to-point line drawing,
    rectangle outline/fill, manual grid borders, region copy/paste, and whole-grid shifting.
  - This is the normal manual-art entry point when you want to draw in code.
- PixelGenerator.render(PixelArt art)
  - Use this when you already have a String[][] grid, including one loaded from a text-grid file.
  - Validates input.
  - Resolves final divisible output dimensions.
  - Applies an optional pixel border outside the content area.
  - Renders in memory.
  - Performs one final buffered PNG write.
  - Returns the resolved absolute output path.
- PixelGenerator.render(PixelColorArt art)
  - Use this when your source grid is Colors.Color[][] rather than token strings.
  - Validates the direct-color grid shape.
  - Resolves final divisible output dimensions.
  - Applies an optional direct-color pixel border outside the content area.
  - Renders exact RGB values in memory.
  - Performs one final buffered PNG write.
  - Returns the resolved absolute output path.
- PixelGenerator.render(PixelGridBuilder builder)
  - Converts the builder into a PixelArt snapshot.
  - Renders through the normal PixelArt pipeline.
- PixelImageQuantizer.quantize(String inputPath, int outputWidth, int outputHeight)
  - Reads an image from disk.
  - Compresses the full source image into the requested token-grid size.
  - Averages visible colors within each output region.
  - Ignores transparent source pixels during averaging.
  - Returns a String[][] token grid using the fixed renderer palette.
- PixelImageQuantizer.quantizeToTextGrid(String inputPath, int outputWidth, int outputHeight, String outputPath)
  - Quantizes an image and writes the result as a reusable text-grid file.
  - Ignores the supplied output extension and always writes a .txt file.
- PixelImageQuantizer.writeTextGrid(String[][] grid, String outputPath)
  - Writes any existing token grid to the same reusable text-grid format.
  - Ignores the supplied output extension and always writes a .txt file.
- PixelImageQuantizer.loadTextGrid(String inputPath)
  - Reads a saved text-grid file back into String[][] so it can be rendered or edited later.

Typical Flows
- Manual token art in code
  - Create PixelGridBuilder
  - Draw into it with setCell / drawLine / fillRect / fillBackground / fill / etc.
  - Call builder.render() or PixelGenerator.render(builder)
- Render an existing token grid
  - Create PixelArt from String[][]
  - Call PixelGenerator.render(art)
- Save token art as text for reuse later
  - Call PixelImageQuantizer.writeTextGrid(grid, outputPath)
- Quantize a normal image into a reusable text grid
  - Call PixelImageQuantizer.quantizeToTextGrid(inputPath, width, height, outputPath)
- Load a saved text grid and render it
  - Call PixelImageQuantizer.loadTextGrid(inputPath)
  - Wrap the returned String[][] in PixelArt
  - Call PixelGenerator.render(art)

Common Builder Commands
- setCell(x, y, token)
  - Set one grid cell to one palette token.
- clearCell(x, y)
  - Reset one grid cell back to transparent.
- clear()
  - Reset the whole builder grid back to transparent.
- fillBackground(token)
  - Fill the whole builder grid with one token.
- fill(startX, startY, token)
  - Flood-fill a connected region starting at one cell.
- replace(fromToken, toToken)
  - Replace every matching token in the current grid.
- drawLine(x1, y1, x2, y2, token)
  - Draw a Bresenham-style line between two cells.
- drawRect(x1, y1, x2, y2, token)
  - Draw a rectangle outline between two corners.
- fillRect(x1, y1, x2, y2, token)
  - Fill a rectangle between two corners.
- drawBorder(token, thickness)
  - Draw a border into the art itself, measured in cells.
- copyRegion(x, y, width, height)
  - Copy a rectangular region out of the current builder grid.
- pasteRegion(destX, destY, region)
  - Paste a copied token region into the current builder grid.
- shift(deltaX, deltaY)
  - Shift the whole grid contents by a cell offset.
- copyGrid()
  - Get a defensive copy of the whole token grid.
- toPixelArt()
  - Convert the current builder state into a PixelArt request.
- render()
  - Render the current builder state to PNG immediately.

Normalization Rules
- null -> transparent
- trim surrounding whitespace
- lowercase token
- blank after trim -> transparent

Palette Rules
- Palette is hard-coded.
- Unknown non-blank tokens throw.
- Full palette reference currently lives in `PixelTokenSupport.java`.
- The palette includes:
  - transparent aliases like ., transparent, clear, none, blank
  - core single-letter tokens like b, r, g, u, y, c, m, o, p, s, w
  - short aliases like lb for light blue
  - many full descriptive color names like carrot, emerald, lavender, goldenrod, tomato, orchid, ruby, sapphire
  - grayscale, reds, pinks, oranges, yellows, browns, greens, cyans, blues, purples, and utility accent colors
- The token table is intentionally large so art can stay readable without exposing extra renderer API.

Render Request Rules
- Grid must not be null.
- Grid must contain at least 1 row.
- Every row must exist.
- Every row must contain at least 1 column.
- All rows must have the same number of columns.
- Direct-color grids follow the same rectangular rules.
- Direct-color grid cells may be null and will render as transparent.
- Preferred width must be > 0.
- Preferred height must be > 0.
- Output path must not be null or blank.
- Output path must include a .png file name.
- Parent directory of the output path must already exist.
- Border size must be >= 0.
- Border color is required when border size is greater than zero.

Sizing Rules
- Preferred width and preferred height are handled separately.
- Preferred width and preferred height describe the rendered content area.
- The final width must be evenly divisible by the column count.
- The final height must be evenly divisible by the row count.
- If a preferred size is not evenly divisible, round to the nearest divisible size.
- If rounding is exactly tied, round up.
- Cell width = resolved content width / columns.
- Cell height = resolved content height / rows.
- Cell width and cell height do not need to match.
- Every cell in the render shares the same cell width.
- Every cell in the render shares the same cell height.
- If a border is enabled, final output width = resolved content width + (2 * border size).
- If a border is enabled, final output height = resolved content height + (2 * border size).
- The border is measured in pixels, not cells.

Rendering Model
- Rendering is fully in memory.
- One BufferedImage is created.
- No temporary files.
- No staged disk writes.
- One final buffered PNG write directly to the target file.
- The renderer does not mutate the PixelArt object or its grid.

Transparency Rules
- The token "." is fully transparent.
- Null cells are fully transparent.
- Blank cells are fully transparent.
- Transparent cells produce literal transparent pixels in the PNG.
- Border color uses the same token palette and normalization rules as grid cells.
- In direct-color mode, a null Colors.Color cell is fully transparent.
- In direct-color mode, non-null Colors.Color cells are always written as opaque 0xFFRRGGBB.
- In image quantization, fully transparent source pixels are ignored when averaging a region.
- If a quantized region has no visible source pixels, its token is ".".

Current Scope
- Focus on direct grid-to-PNG rendering for both token-based and direct-color inputs.
- Include image-to-grid quantization into renderer-compatible tokens.
- Include a first-pass mutable grid builder object.
- The builder currently includes the core editing and shape methods needed for manual art creation.
- Token-based and direct-color requests both support a render-time pixel border.
- No QR-specific helper in this package yet.
- No semi-transparent palette entries yet.

Coordinate Convention
- origin = top-left
- x increases to the right
- y increases downward
